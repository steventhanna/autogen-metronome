# autogen-metronome

Auto-generated, strongly-typed Rust client for the [Metronome API](https://docs.metronome.com/).

Generated from the official Metronome OpenAPI spec (`https://api.metronome.com/v1/docs/openapi`)
using [openapi-generator](https://openapi-generator.tech/).

## Installation

```toml
[dependencies]
autogen-metronome = "0.1"
tokio = { version = "1", features = ["macros", "rt-multi-thread"] }
```

To use only specific API groups (reduces compile time):

```toml
[dependencies]
autogen-metronome = { version = "0.1", default-features = false, features = ["customers", "contracts", "native-tls"] }
```

## Quick Start

```rust
use autogen_metronome::MetronomeClient;
use autogen_metronome::apis::customers_api;

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let client = MetronomeClient::new("your-api-token");
    // Call generated API functions with client.config().
    Ok(())
}
```

## Authentication

Metronome uses a single production environment and an HTTP bearer token:

```rust
let client = MetronomeClient::new("your-api-token");

// Custom base URL (proxy, mock server, testing):
let client = MetronomeClient::with_base_url("your-api-token", "http://localhost:8080");
```

## Feature Flags

All 15 API groups are enabled by default. Use `default-features = false` and select only what you need:

| Feature | API |
|---------|-----|
| `alerts` | Alerts |
| `billable-metrics` | Billable metrics |
| `contracts` | Contracts |
| `credits-and-commits` | Credits and commits |
| `custom-fields` | Custom fields |
| `customers` | Customers |
| `invoices` | Invoices |
| `named-schedules` | Named schedules |
| `notifications` | Notifications |
| `packages` | Packages |
| `products` | Products |
| `rate-cards` | Rate cards |
| `security` | Security |
| `settings` | Settings |
| `usage` | Usage |

**TLS features:** `native-tls` (default) or `rustls`. One of them must be enabled — if you set
`default-features = false`, remember to add `native-tls` or `rustls`, or HTTPS requests will fail.

## Nullable Fields

The Metronome API marks many fields as both optional and nullable. This crate distinguishes the
three states using `Option<Option<T>>` (via `serde_with::double_option`):

```rust
field: None          // omitted from JSON
field: Some(None)    // sent as null
field: Some(Some(v)) // sent with value
```

## Regenerating from the Spec

```bash
# Requires: brew install openapi-generator
./generate.sh
```

This fetches the latest spec, records its hash in `SPEC_HASH`, runs the generator, applies
post-processing fixes for known spec bugs (currently none needed), re-applies feature gates, and
verifies compilation.

## Architecture

- **Types and API methods** are auto-generated by openapi-generator from the Metronome OpenAPI spec.
- **`MetronomeClient`** is a thin hand-written wrapper that sets the bearer token, base URL, and
  user-agent.
- **Generated code is committed** — no build-time generation, no proc macros. Run `./generate.sh`
  to update when the spec changes.
